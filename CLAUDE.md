## What this is

A Spring Boot 4.1 / Java 21 **REST BFF** (`product-rest-bff`, port `8081`) that exposes `/api/products` as JSON and forwards every call to an external gRPC `product.v1.ProductService` (default `localhost:9090`). It has no database; the gRPC server is the source of truth. Design spec: `docs/superpowers/specs/2026-09-16-product-rest-bff-design.md`.

## Commands

```bash
./gradlew build                      # compile (incl. proto codegen) + tests
./gradlew test                       # all tests — none need a running gRPC server
./gradlew test --tests 'com.example.rest.product.ProductControllerTest'
./gradlew test --tests 'com.example.rest.product.ProductControllerTest.create_returns201'
./gradlew generateProto              # regenerate stubs after editing product.proto
PRODUCT_GRPC_HOST=localhost PRODUCT_GRPC_PORT=9090 ./gradlew bootRun
```

`bootRun` starts even if the gRPC server is down; requests then return `503` ProblemDetails.

Full stack in Docker (Postgres → gRPC product API built from `../grpc_client` → this BFF on `:8081`):

```bash
docker compose up --build -d
PRODUCT_API_CONTEXT=/path/to/grpc_client docker compose up --build -d   # if the server repo lives elsewhere
docker compose down -v                                                  # stop and wipe the Postgres volume
```

Postgres belongs to the gRPC API; the BFF only receives `PRODUCT_GRPC_HOST=product-api`. Don't run this stack alongside `../grpc_client`'s own compose file, because both publish `5432` and `9090`.

## Architecture

Request flow: `ProductController` → `ProductGrpcClient` → `ProductServiceBlockingStub` → gRPC server.

- **Proto contract** — `src/main/proto/product.proto` is a *copy* of the upstream server's contract (Java package `com.example.product.v1`, generated by the `com.google.protobuf` Gradle plugin with the `grpc` plugin enabled). Keep it in sync with the server rather than changing it unilaterally.
- **Stub wiring** — there is no hand-written channel/stub config. `@ImportGrpcClients(target = "product", ...)` on `ProductRestApplication` creates the blocking stub bean, and the `product` channel target comes from `spring.grpc.client.channel.product.target` in `application.yml`.
- **Proto isolation** — only `ProductGrpcClient` and `ProductDtoMapper` touch generated proto types. Controllers work purely with REST DTO records (`CreateProductRequestDto`, `AdjustStockDto`, `ProductResponse`, `ProductListResponse`). Price is a **string** end to end (decimal-as-string in proto); timestamps become `Instant`.
- **Deadlines** — every call goes through `ProductGrpcClient.stub()`, which applies a 3-second deadline. New RPC methods must use `stub()`, not the raw field.
- **Proto3 null handling** — proto setters reject `null`, so optional DTO fields (e.g. `description`, `q` → `name_contains`) are converted to `""` before building requests.
- **Error mapping** — `GrpcExceptionAdvice` turns `StatusRuntimeException` into RFC 7807 `ProblemDetail`: `NOT_FOUND`→404, `INVALID_ARGUMENT`→400, `UNAVAILABLE`→503, `DEADLINE_EXCEEDED`→504, anything else→502. Only 404/400 pass the upstream description through; the rest use a generic detail. Every response includes a `grpcCode` property. Controllers signal REST-level errors by throwing gRPC `Status` exceptions so they go through the same path (e.g. `DELETE` throws `NOT_FOUND` when `deleted=false`).

## Testing conventions

- `ProductControllerTest` — `@WebMvcTest` + `@MockitoBean ProductGrpcClient`; checks HTTP status codes, JSON shape, validation, and ProblemDetail bodies.
- `ProductGrpcClientTest` — plain Mockito on `ProductServiceBlockingStub`. You must stub `withDeadlineAfter(3, TimeUnit.SECONDS)` to return the same mock, or calls hit an unstubbed stub.
- `ProductDtoMapperTest` / `GrpcExceptionAdviceTest` — pure unit tests.
- Spring Boot 4 split test starters: `@WebMvcTest` lives in `org.springframework.boot.webmvc.test.autoconfigure`, not the Boot 3 package.
